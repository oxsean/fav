# 界面

任务层的 TUI 与 Web 界面：定稿的取舍、原则、操作表与快捷键、URL 状态、主题与皮肤、首页综合看板、TUI 的完整交互和页面清单。实现：`internal/server/web`（`core/actions.js`、`core/router.js`、`core/prefs.js`、`pages/`，结构见 [runs/clients.md](../runs/clients.md)「Web UI」）、`internal/skin`、`internal/ui/tui`（`taskviews.go`、`taskanswer.go`、`taskedit.go`、`undo.go`、`theme.go`、`keys.go`）。

## 定稿

- 看板五列（等你 / 运行中 / 排队 / 未开始 / 已结束），不分「评审中」列；阶段写在卡片上。
- TUI 首页、列表、树、看板是任务页的四种排列（`o` 轮换），不另开标签页；分屏保持上下两栏、下栏只读。
- 「等你」排序：挡住 agent 的（权限、提问）在前，其余按等待时长。
- 「本次 run 都允许」不做：节点拿不到 agent 的「以后都允许」选项；权限只有允许一次和拒绝（可附一句理由）。
- 登录前的页面不显示任何计数；登录方式只在 `config.json` 里配，网页只读列出。节点侧的目录和原生会话共享（`projects.<id>.dirs`、`share_sessions`）在网页上只读显示。
- 预算、打回轮数属于 workflow，项目设置里不单列。
- 界面密度只有一套，不另做「精简版」。

## 原则

1. 主界面是按状态分组的列表加详情，「等你」永远排第一，而且就地处理。看板和树只是任务的另外两种视图，不当首页。
2. 一行说清：每个 run 一行，依次是状态图形（形状 + 颜色，运行中带动画）、任务、阶段、机器、agent/模型、最后一句话、耗时、token/花费。
3. 密度靠减少装饰，不靠缩小字号：
   - 默认行高 32px、字号 13px；紧凑档 28px，宽松档 40px（多一行摘要）；
   - 数字用等宽数字；
   - 1080p 下任务列表一屏不少于 20 行。
4. 快捷键优先：一张**操作表**生成 Web 的 `⌘K`、TUI 的 `:` 命令面板、`?` 帮助和按钮上的键提示，测试保证每个操作都有键、都搜得到，中英文名都能搜。TUI 一侧这张表就是 `keys.go` 的 `bindings`，不另起一套。
5. 速度：交互 < 100ms，写操作 < 500ms；写命令带 `command_id`，可以先改界面，失败再回滚。加载指示 200ms 后才出现，出现后至少停留 400ms。
6. 能撤销就不确认：小写的可逆操作立即生效，给 6 秒撤销提示；会启动 agent 的、停止、放弃、删除仍走确认对话框（沿用 TUI 的字母语义）。
7. 状态进 URL：视图、筛选、选中项、抽屉都在 URL 里，刷新后原样恢复。

### 操作表（Web）

- 操作表在 `core/actions.js`，一行一个操作：`id`、键、作用域层级、分组；中英文名在 `act.<id>`。做什么由组件用 `useActions` 绑定（`core/keys.js` 的作用域栈决定此刻哪个生效）。
- 由它生成：
  - `⌘K` / `Ctrl+K` 面板：列出此刻生效的操作，按两种名字、id 和键搜索，开头匹配的排在前面；输入里有字时还列出匹配的任务、运行和机器；
  - 按键：`g` 加一个字母去各页，`Shift+字母` 切主题、语言、密度，`d` / `e` / `x` 对选中任务打开对话框；
  - `?` 快捷键页；
  - 键栏和按钮上的键提示。
- 输入法的 `；` `，` `？` `、` 当作 `;` `,` `?` `/`。
- `select_test.js` 确认：表和设计的键表一致，每个操作有键、有中英文名、两种名字都能把它搜到；同一个作用域里一个键只绑一个操作。
- Web 的表只管 Web 的页面，TUI 的面板从 `bindings` 生成，两边守同一套规则，不共用一个文件：两边的操作集合不同，共用会让每一边都带上对方用不到的操作。

### 命令面板（TUI）

- `:`（输入法下 `：`）打开命令面板。
- 条目取自帮助页 `helpLayout` 里列表范围的每一行（成对的移动键除外），一个动作一条：键加当前语言的说明。
- 用两种语言的说明搜索（`i18n.In`）；选中后，按它在 `bindings` 里的第一个键执行，和直接按键走同一条路。
- `palette_test.go` 确认：每条都能用中文和英文说明找到，它的键能被按出来。

### URL 状态（Web）

`core/router.js`：查询串里放 `page`、`view`（`list` | `board` | `tree`）、`task`、`run`、`wait`（首页上一条等你的事的落地页）、`sessions` 和 `session`（机器页下一台机器的会话和打开的那个），等于默认值时省略。筛选不进地址（会话页的筛选只在页面里，不记），记在浏览器里（任务页 `tend-task-filter`、运行页 `tend-runs-filter`）。

切换页面、手机上打开一个任务或运行用 `pushState`，所以浏览器和手机的返回能回到上一层；电脑上换选中用 `replaceState`。`#task-<id>`（通知和 webhook 里的链接）打开任务页并选中它，`#task-<id>/r-<运行>/e-<事件>` 还滚到那一步。以前的 `?page=inbox` → 首页，`settings` → 我，`projects` → 团队。

## 主题、皮肤、多语言

- 皮肤由一个 Go 生成器产出：输入是底色、强调色、对比度，在 LCH 空间派生出全部语义 token，亮暗各一套。
  - 内置预设也用这个生成器生成。
  - Web 由服务端出 `/theme/<skin>.css`，因为 CSP 不允许内联样式；TUI 用同一份 token 生成配色，降到 256 色、16 色，也支持 `NO_COLOR`。
- 对比度由测试保证：正文 ≥ 4.5:1，图形和边框 ≥ 3:1；不达标时生成器自动调亮度，不报错交给用户。
- **状态色独立于强调色**：每个状态有固定色相，外加独立形状，灰度截图里也能分清。
- 设置项：亮 / 暗 / 跟随系统、3–4 个预设加自定义、对比度（标准 / 高）、密度三档，都能实时预览。
- 中英文各截一次图：Web 1280 / 375 宽，TUI 80×24 / 120×34。Web 在输入法组字时（`isComposing`）忽略快捷键；数字和时间用 `Intl` 格式化。

### 皮肤（Web）

- 生成器 `internal/skin`：输入底色、强调色、对比度，在 CIE LCh 里派生 26 个 token，亮暗各一套。
  - 中性色取底色的色相，彩度封顶 12；
  - 状态色各有固定色相，不随强调色变；
  - 每个前景色沿亮度离开背景，直到对它可能落在的每个底色（bg、surface、surface-alt、surface-hover，状态色还有对应的 soft 底）都达标：标准档文字 4.5:1，高对比度档 7:1；焦点环 3:1；高对比度档的边框 3:1。
  - 标准档的分隔线算装饰，不设门槛。
- 预设 tend、forest、ember、graphite。
- 皮肤名 `<预设>[-<rrggbb 强调色>][-high]`，由 `/theme/<name>.css` 出样式，`/theme/presets.json` 出预设列表。
- `css/` 里不写任何颜色，颜色只用皮肤 token。
- 测试覆盖：
  - 每个预设 × 两档对比度 × 亮暗都达标；
  - 极端强调色和底色也达标；
  - 页面用到的每个 `var(--x)` 都有定义。
- 设置存在浏览器的 `localStorage`（`core/prefs.js`）：主题、语言、密度由 `Shift+T` / `Shift+L` / `Shift+M` 和用户菜单切换；皮肤、强调色、对比度在「我」页的外观里改（`tend-look`），那里也能改前三项。
- 密度只改行高，字号都是 13px：
  - 紧凑 28px；
  - 标准 32px，一行放状态图形、标题、处境、耗时；
  - 宽松 40px，多一行摘要：任务 id、机器 / agent、run 状态。
- 运行中的状态图形会脉动，系统设置了减少动效时不动。

### 皮肤（TUI）

- 颜色全部来自同一个生成器：`theme.go` 按终端报的背景取皮肤的亮或暗一侧，由终端的颜色档位降到 256 / 16 色，`NO_COLOR` 下不出颜色。
- token 对应：
  - `accent` / `text` / `muted` / `faint` / `border`；
  - 选中行和主按钮底用 `accent-soft`；
  - 搜索命中用 `warning-soft` 底；
  - 浮层背后的底图：亮色用 `faint`，暗色用 `border`。
- 生成器为 TUI 多出一个 `faint`（图形级，3:1）。测试另外保证正文落在 `accent-soft`、`warning-soft`、`danger-soft` 上也达标。
- 设置面板里有皮肤、强调色（`#rrggbb`，不合法就清空）、对比度，改了立即生效，存进 `config.json`（`skin`、`accent`、`high_contrast`）。
- `TestEverySkinDrawsInBothThemes`：4 套皮肤 × 亮暗两套主题 × 三个画面，每一帧都是终端宽度，屏幕上出现的是这套皮肤的强调色。

## 首页综合看板

- 等你永远在最前，就地回答或放行；等你为空时收成一行，不留大块空白。
- 所有区块靠推送更新；手机上首页只留等你和在跑。
- TUI 首页：上方「等你」，中间运行表，底部机器和用量各一行；80×24 时只留前两块。

### Web（`pages/home.js`，默认页）

- 上面四个数：等你（按要回答、出错、待验收、其他分组计数，最久一条等了多久）、在跑 / 排队（机器的 `活跃/上限`，今天每小时的并发）、今天结束（按结束状态）、今天花费（近 7 天的小折线）。
- 等你：按上面的分组排，组内等得最久的在前，可以只看「我负责」「我验收」；每条就地处理：问题的选项（`1`–`3`）、权限的允许 / 拒绝、待验收的完成（可撤销）、出错的重试（先确认）；展开后是它刚做的三步和整份作答表单。
- 在跑 / 排队：在跑的在前；每行写节点报的当前动作（没有就是 note、最后一句话），排队的写它在等什么；带时长、花费和停止（先确认）。
- 最近结束、今天的运行（每台机器一条泳道）、近 7 天的用量（按 provider 堆叠）和结果比例。
- 手机上只有等你和在跑两块，图表不画：等你按「为什么是你」筛选（多一个「我派发的」），每条只有一个快捷操作（允许、完成、重试或打开），点一行进它的落地页作答并写明回答去哪，答完自动换到下一条，返回回到等你；通知也落在这一页；在跑只列在跑的，排队的只计数。每个数的来源和手机上的细节见 [runs/clients.md](../runs/clients.md)「首页」。

### TUI（`taskviews.go`）

任务页按 `o` 轮换四种排列（首页 / 列表 / 树 / 看板），默认首页，不另开标签页；分屏保持上下两栏、下栏只读。

- 「等你」排序（`task.State.NeedsYou`，Web 收件箱同用一份）：挡住 agent 的（权限、提问，`Run.Blocking`）排最前，其余按等待时长。
- 首页：「等你（N）」列出处境是等你的任务（没人派发的也算），「运行中（N）」列出处境是运行中的（排队的不在首页，在列表和看板里）；终端高于 24 行时底部加机器（状态、`活跃/上限`）和 7 天用量（run 数、token、花费）各一行。第一条挡住 agent 的任务在它那一行下面就地展开：一个提问给出编号选项，选中的有说明时下一行写它，数字键 1–9 选、Enter 发送；一个权限请求给出 Enter 允许、`n` 拒绝（可以再打一句理由，Enter 发送、Esc 取消），不做「本次都允许」。
- 列表：等你、未完成、已结束三组，每行按剩余宽度从右边依次收窄：标题栏的「共 N 个」是筛选匹配的任务数，与排列无关；运行中的行是编号（短 id）、阶段、机器、agent/模型、run 的最后一句话、耗时、token/花费；等你的行是等待的种类（退出码 0 的结束是「待确认完成」，非 0 才是出错）、编号、它问了什么或要用什么命令、等了多久；排队和其他行只写处境；80×24 时仍然可读。
- 树：子任务缩进在父任务下面；父任务被筛掉时子任务当顶层。
- 看板：五列同 Web（取消的归入已结束），占满宽度、不显示详情栏。
  - 卡片三行：编号和标题；workflow 阶段面包屑（当前阶段用方括号标出，没有 workflow 就显示处境）；agent@机器 · 处境 · 打回次数（↺n）· 子任务进度（done/total）。同样按宽度从右边收窄。
  - `h` / `l` 跳到左右最近的非空列，行号保留或取该列最后一行，`j` / `k` 在全体卡片里顺序移动；底部提示行给出 `h l` 切列、`j k` 切卡片。
  - 筛选框除了纯文本，还认 `project:<id>`、`stage:<name>`、`needs:you`。
- 答复对话框（`taskanswer.go`）：选项支持数字键 1–9 直接选，选中的选项有说明时写在选择器下面，单选一题时另给一个「用你自己的话」的自由文本框（非空时覆盖选中项），拒答 / 拒绝都能在一个理由框里打一句话再发送（`coord.Answer` 的 `Message` 字段，节点转给 agent）。

## TUI 完整交互

以下流程都能在 TUI 里完整做完：回答、插话、派发 / 停止、看板和树、拆解评审、任务 / 项目 / agent 编辑、设置和皮肤。

- 长文本走 `$EDITOR`；diff 交给 lazygit 或 difftool 未实现。
- 交互：命令面板、区间多选、撤销、跟随暂停并显示新消息计数、分屏盯两个 run、窗口标题显示等你的数量。

### 实现（`taskedit.go` 等）

- 任务对话框：没有子任务、没有草稿的待办任务有「拆解」（`task.plan`，用项目的 planner）；有草稿时「草稿（N）」是主按钮，「跑起来」不再是。
- 草稿对话框：子任务按父子缩进，每条下面一行 key、规模、workflow、角色、先完成谁；再列 planner 的问题；按钮「按草稿建任务」（Enter，`task.plan_apply` 带 `expected_rev`）、「编辑」（`e`）、「丢弃」（先确认，返回草稿）。
- `$EDITOR` 往返：写进临时文件，`$VISUAL` / `$EDITOR`，都没有就 `code --wait`，TUI 让出终端直到编辑器退出。没改动就不发；本地校验不过或协调器拒绝时，改过的文字按对象留在内存里，下次编辑从它接着改，保存成功才清掉。
  - 草稿：JSON，和 `tend task draft --save` 读的同一种；
  - 项目设置（任务对话框的「项目设置」）：name、owner、repos、links、context、defaults、hooks、fetch、workflows 的 JSON，不认识的字段拒收，只发改了的字段（`project.edit`）；
  - agent 定义（运行对话框的「编辑 agent」「新建 agent」）：Markdown，先在本地 `defs.Parse` + `defs.Check`，再 `agentdef.save`；选中的是 config.json 里的档案而不是定义时直接说明。
- 撤销（`undo.go`）：收藏、归档、会话完成、任务完成 / 重开这些可逆操作的提示后面带「u 撤销」，6 秒内 `u`（输入法下 `Ctrl+Z`）撤回，提示也至少停留 6 秒；撤回的是改之前的那个字段值（收藏时间原样还原），任务的完成 / 重开发 `task.undo` 点名那次写，一次操作只撤一次。
- 区间多选（任务列表）：`Shift+↓` / `Shift+↑` 从起点扩选，行首标 `*`；`x` 把选中的全部标完成（全都已结束时全部重开），可撤销；`Enter` 打开一个运行对话框，把其中待办且没在跑的一起派发到同一台机器、同一个 agent，补充的那句每条都带上；`Esc` 清除，换排列也清除。
- 分屏盯 run：任务对话框「盯在旁边」把这个任务最近的 run 固定在详情下方（各占一半，终端太矮时不分），换选别的任务仍在，输出照常随 `run.output.watch` 推来；「不再盯」取消。
- 跟随暂停：会话对话栏停在旧消息时不插入新消息，位置栏显示「N 条新消息」（`live.go` 的 `refreshChat`）。
- 窗口标题：`tend · N 个等你`，N = Agents 页等你的会话 + 等你的任务。

## 页面结构与用词

Web 的首页、任务、运行、机器、Agent、团队、我按下表做好了；TUI 的改名还没做。

### 用词

一个概念只用一个词，两个界面相同：

| 概念 | 用词 | 不再用它指这个 |
|---|---|---|
| 团队项目：权限、仓库、默认值、hooks | 项目 | TUI 的会话按目录分组改叫「目录」（`Dirs`） |
| 能跑任务的 agent：`config.json` 的 profile 和 Markdown 定义合成一个列表，详情里写来源 | Agent | 「档案」「定义」只在详情里作来源说明 |
| Herdr 里此刻在跑的会话 | 在跑（`Running`） | TUI 的「Agents」标签 |
| 当前身份 | 用户的名字；没有名字时「服务器管理员」 | `server host`、`local`、「个人工作区」 |

### Web 页面

| 页面 | 包含 | 并入的 |
|---|---|---|
| 首页 | 等你（按「为什么是你」和类型筛选、就地作答）、运行中（前几条和「全部」）、机器摘要 | 「等你」页 |
| 任务 | 列表 / 看板 / 树，任务详情 | — |
| 运行 | 全部 run：对齐的表格，右侧预览 | — |
| 机器 | 连接、负载、主人与分享；一台机器自己的会话（「会话」，见 [runs/clients.md](../runs/clients.md)「会话页」） | 机器页下方的 agent 列表移到「Agent」 |
| Agent | 全部可用 agent：来源、类型、模型、装在哪些机器上；新建与导入 | 「Agent 定义」 |
| 团队 | 项目、成员、邀请、准入规则、审计 | 「项目」「管理」 |
| 我 | 账号、登录方式、token 与浏览器会话、外观与语言 | 「账号」「设置」 |

「会话」页挂在机器下面（主人和管理员从一台机器的事实进去），不在侧栏占位。手机上的范围见 [runs/clients.md](../runs/clients.md)「Web UI」：底部四个标签（等你、任务、运行、我），整个业务流程都能做完，设置和管理不在手机上做。

### TUI

- 标签页：收藏、会话、目录、在跑、任务；功能不变，只改名。
- 任务页的四种排列按同一个处境（`task.State.Situation`）分组，与看板的五列一致。

## 页面清单

- 页面：首页、收件箱、运行、项目看板 / 列表 / 树、任务详情、拆解评审、项目、agent 定义、workflow、机器、会话、设置（主题 / 皮肤 / 密度）、设计规范；
- 手机：首页 + 作答。
- 采纳 Multica 的界面细节：
  - 运行行显示当前在执行的命令和耗时，并带停止按钮；
  - 顶部显示「N 个 agent 在跑」；
  - 父任务卡片带子任务进度环；
  - 阶段推进作为一条记录写进任务时间线；
  - 任务级 token / 费用合计；
  - 派发前可以选「确认」或「先不开始」。
- 避开 Multica 的上手摩擦：
  - 网页上建项目能直接选「机器 + 目录」，目录列表由节点提供；
  - 新建 agent 的第一步就选类型和模型；节点只报告 CLI 装没装、登没登录，不报告模型，所以模型按名字或别名手输，给出常用别名，并在框下说明原因；
  - 发送键在所有输入框里行为一致（`⌘Enter` 发送，`Enter` 换行，多行框和单行框都在界面上写明）；
  - 消息发送框写明消息会去哪（见 [workflows.md](workflows.md)「消息与插话」）。

### Web 的页面细节

- 首页运行行带停止按钮（先确认），行里是 agent 最后报的进度或最后一句话；顶栏显示「N 个 agent 在跑」（运行中和启动中）；首页「运行中」的数字同一口径，排队的另写「排队 N」；运行页的筛选「未结束」包括排队。
- 父任务的列表行和看板卡片带子任务进度环（完成数 / 未取消的子任务数）。
- 任务详情的元数据里有「全部运行」：各次运行的 token 和花费合计。
- 派发对话框：「确认并排队」之外有「先不开始」，把待办任务放进未开始，可撤销。
- 发送键：所有多行框 `⌘Enter` / `Ctrl+Enter` 提交所在表单，`Enter` 换行；消息框下方写明「⌘Enter 发送 · Enter 换行」，首页的单行回复框写「Enter 发送」；快捷键页也列出。
- 消息去向写在框下：插话框「发给正在跑的 <run>：它在这一轮里读到」，回复框「作为 <run> 的回复：同一个会话里新开一个后台运行」；workflow 任务的消息框沿用按阶段的去向说明。
- 撤销：改状态（完成、重开、先不开始、首页标记完成）的提示带「撤销 ⌘Z」按钮，6 秒内按钮或 `⌘Z` / `Ctrl+Z`（不在输入框里时）撤回到原状态（`task.undo`，不是重开，见 [workflows.md](workflows.md)「撤销」）；操作表里是 `undo`。
- 阶段推进：`task_staged` 折叠进任务的 `stages`（时间、阶段、轮次、是否退回，最近 50 条），任务的工作记录按时间列出「进入 X 阶段」「退回 X 阶段（第 n 轮）」。
- 看板拖动：卡片拖到「已结束」= 标记完成（待办、没在跑、不是 workflow 任务），拖到「未开始」= 先不开始，把未开始的拖到「排队 / 运行中」= 开始，把结束的拖回「等你」= 重开；可放的列拖动时描虚线框，其余列拒绝并提示规则；改状态的都可撤销。
- 新建 agent（「Agent」页）先填名字、类型（标出装在哪些机器上）、模型、角色，再进入整份 Markdown 定义。
- 等你（首页）：每条带「为什么是你」（`inbox.watch` 的 `as`：负责人 / 验收人 / 派发人），按类型（要回答、待验收或收尾、出了问题、其他）分组，可以按身份筛选。
- 作答：首页上数字键按快捷操作的顺序作答（焦点不在输入框时）：权限请求是允许、这次运行里都允许（给了才有）、拒绝；只有一个单选问题时是它的前三个选项。拒绝的理由（作为 `message` 转给 agent）和「其他」自己写的回答在展开后的作答表单里。
- 「运行」页（`g r`，`pages/runs.js`）：全部 run 从新到旧，按状态（未结束、失败、已结束）和机器筛选；电脑上选中一条在右边预览它的概况和输出，可以打开它自己的页或跳进任务。
- 看板卡片：编号、打回次数 `↺n`、花费、子任务环、标题、阶段 chip（第几轮）和阶段条、agent@机器、进行中 run 的耗时；方向键在卡片间移动。
- 任务详情没写机器或 agent 时显示项目的默认值并标「项目默认」（agent 取 `defaults.agent`，没有就取 `roles.implement`）；内置用户 `local` 显示为「服务器管理员 / Server admin」；run 的目录优先显示节点报告的 `worked.dir`（真实的工作树），`tend run show` 同样。
- 任务详情：workflow 块头写「预算 $花费 / $上限 · 分钟 / 上限」（`flow.budget`，按本任务各 run 合计）；工作记录里每个 run 带耗时和花费；元数据的「全部运行」在不止一个 provider 时按 provider 拆开。低于半分钱的花费不显示。
- 拆解评审：planner 有会话时随时可以「补充意见，重新拆解」（不只在它提问时）；草稿头写 planner、耗时、花费、最后改的人和依据的需求版本（`#n 第 k 版`）。
- 顶栏：在跑的 agent 数、离线的机器（警示色）、今天的 token 和花费。
- agent 定义页（「Agent」页）：每条带版本（`rev`）和更新时间、被哪些项目的角色和多少个未完成任务用着；「启动参数」给出运行时启动的命令（`agentdef.list` / `get` 的 `launch`：编译后按 headless 流式启动拼出的 argv，目录和任务书出现在 argv 里时写成 `<dir>` `<brief>`），另有警告和全文，可「导出 .md」；页头「导入 Claude Code subagent」把粘贴或读进来的文件放进编辑器，确认后保存。
- 项目设置（「团队」页，还没做）：四个 hook（setup、before_run、check、cleanup）各一个输入框；「检查目录」对 repos 里每个 `机器=目录` 问那台机器（`node.dirs` 列它的上一级），标出存在且是 git 仓库、存在但不是、不在或不在允许的目录里。
- 新建项目（「团队」页，还没做）可选「机器 + 目录」：列出你能用的在线机器，目录由节点方法 `node.dirs` 按 `node.allow_dirs`（没配时是家目录；不看 `projects.<id>.dirs`）列出，跳过点开头的目录，标出 git 仓库，一次最多 500 项；路径先解析符号链接再和根比，根外或相对路径回 `unauthorized`；可进入子目录和返回上一级；选定后项目得到一个 repo，名字取目录名，`dirs` 里记这台机器的路径。
