# 原生 TUI

原生 TUI 的 Agents 页（跑着的会话、Herdr、「需要你」）、布局阈值、视觉约定、键盘与鼠标。实现：`internal/ui/tui`（键表 `keys.go`、`attention.go`、`theme.go`、`zone.go`、`view.go`、`input_unix.go` / `input_windows.go`）、`internal/capture`（`live.go`、`ReadPulse`、`HookWaiting`）、`internal/herdr`、`cmd/tend`（`install-hook` / `hook-event`）。

标签页改名（「Agents」改「在跑」，计划）见 [ui.md](../tasks/ui.md)「页面结构与用词（计划）」。

## 跑着的会话（Herdr）

目标是盯着这个面板就知道各个 agent 的进展，不用一个个 tab 翻。第四个标签页「Agents N」只列此刻在
跑的（查询上等于 `status:live` + `turns:0`），**不分组、按会话开始时间排**（新开的在上，索引还没有的当最新）：
状态三秒一变、活跃时间十秒一变，按它们排卡片会跳来跳去，盯着看反而找不到刚才那条；状态只在卡片上标颜色。
`o` 轮：按状态分组（等你 / 跑完了未看 / 工作中 / 空闲 / 跑完了，Herdr blocked 但已处理或暂缓的仍归「等你」，组内仍按开始时间）→ 按最后活跃（会跳，但要找刚动过的时候有用）→ 回到按开始时间，记在 `config.live_sort`；
索引里还没有的刚开的会话也列，卡片用来源给的标题和目录凑（没有就标短 id，时间留空）；记录文件用 `idx.Transcript(id)` 按前缀找（skip 的、没说过话的文件和续接链的旧 id 都算），所以 SDK 或 Multica 拉起的会话右栏也能读到对话。

卡片第三行写这个 agent 的现状（`capture.ReadPulse` 读记录尾部 512KB，按大小 + mtime 缓存，每次在跑状态刷新后后台读，渲染只查 `m.pulse`）：工作中时「本轮 12 分钟」（从最后一条提示算）、上下文（Codex 取最后一个 `event_msg/token_count` 的 `last_token_usage.input_tokens` / `model_context_window`，写百分比；Claude 取最后一条 assistant `usage` 的 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`，记录里没有窗口，只写 token 数，如 509k；Codex 的 `response_item` 只说明还在这一轮，只有 `task_complete` 算跑完）、「AI：最后一段回复」。恢复检查里，上下文 ≥80%（只 Codex 能算）提示「恢复后很可能先压缩」。

「需要你」（`attention.go`）：每个在跑的会话算一个 `need`——**等你**（Herdr blocked；或记录尾部最后一步是没回答的 `AskUserQuestion` / `ExitPlanMode`，卡片写「等你回答」）、**跑完了未看**（最后是 AI 的回复 / Codex `task_complete`，没在工作，且记录比你上次看过时变大了）。「看过」按记录文件大小记在 `~/.agent/tend/attention.json`（只留在跑的会话）：第一次见到的会话以当时大小为起点（打开 tend 不会把旧输出全算未看）；通过 tend 切过去 / 恢复 / 在 App 打开算看过；`.`（`。`）标已处理（等你的也静音，直到它写出新内容）；`H` 暂缓 1 小时；光标停在卡片上**不算**看过。从「不需要」变成「需要」时底栏提示一次，设置「需要你时」选「底栏提示 + 响铃」再响铃（`\a` 写到 stderr）。标签页写 `Agents 5 !2`，底栏在需要你的会话上多一个 `. 已处理`。`o` 的分组模式按 等你 → 跑完了未看 → 工作中 → 空闲 → 跑完了 排；默认的按开始时间排不变（卡片不跳）。

没有 Herdr 时，权限确认只能靠可选的 Claude hook（`tend install-hook`）：往 Claude 的 `settings.json`（`CLAUDE_CONFIG_DIR` 优先）的 `hooks` 里加 `Notification`（matcher `permission_prompt|elicitation_dialog|agent_needs_input`）、`PermissionRequest`、`UserPromptSubmit`、`Stop` 四组，命令是 `<tend 的绝对路径> hook-event`（`timeout` 5，`async`），已有的不再加（幂等）；改之前留 `settings.json.bak-<时间>`，按原来的键顺序和两格缩进写回（`orderedjson.go`，不认识的内容原样保留），`tend uninstall-hook` 只删命令是 `…/tend* hook-event` 的组，删空的事件键一并删。`tend hook-event` 从 stdin 读 hook 的 JSON，把 `{event, kind, tool, summary, at, size}`（size = 那一刻的记录文件大小；kind 是 `notification_type`，tool 和 summary 是 `PermissionRequest` 的 `tool_name` 和 `tool_input` 的一行，见 [runs/node.md](../runs/node.md)）写到 `~/.agent/tend/events/<session id>.json`，永远 exit 0。读脉搏时（`readPulses`）`capture.HookWaiting`：最新事件是 `Notification` / `PermissionRequest` 且记录文件没有变大 → 算「等你」；批准后工具一跑记录就变大，自然解除；`Stop` / `UserPromptSubmit` 覆盖掉它。`tend doctor` 显示装没装。Codex 不装：它的 `notify` 只有一个命令槽（常被别的工具占用），且只有 `agent-turn-complete`，「跑完了」tend 已经从 `task_complete` 读到。已知局限：tend 没开着时不会提醒。

顶栏「项目 N」是不同项目的个数，不是会话数。实时状态**只在这一页的卡片上标**，
收藏 / 会话 / 项目看的是历史，混进实时状态很怪；详情面板的状态行在哪一页都带（说明 Enter 会切过去）。

- 每 3 秒问一次，三个来源都是读文件级别的开销，**不装 Herdr 也能用**：
  - Claude Code：`~/.claude/sessions/<pid>.json`（它自己写的，带 sessionId / cwd / name / busy|idle / statusUpdatedAt），
    `kill -0` 验 pid 活着；后台会话 `kind=bg` 还带 `jobId`，就是 `claude attach` 用的短 id。
  - Codex：`~/.codex/thread-writer-locks/<thread id>.lock` 被持着 flock 的就是开着的线程（试锁一下，锁不上即活）；
    但 Claude Code 的 Codex 插件起的 `codex app-server` 是常驻进程，它跑过的线程和子代理线程的锁会一直握着，
    所以按 rollout 头一行判 `CodexOneOff` 的不算在跑（每个 id 只读一次）。它跑的 companion task 连 rollout 都不写，只留一把锁：锁开了一分钟还没有 rollout 的也不算（刚开的线程一两秒内就落盘）。它不报忙闲，transcript 15 秒内写过算工作中，否则从最后一次写算空闲。
  - Herdr：`herdr agent list`（4ms），多知道 tab（恢复 = 切过去 / X 关）和 blocked（等你）。
  - 合并时非空字段才覆盖：Herdr 的 tab 和 blocked 叠在 Claude 自己报的 busy/idle 上。
- 分组和详情按 Herdr 的 `agent_status`：`工作中`（强调色）/ `等你`（blocked，红色加粗）/
  `空闲 N 分钟`（灰，时长从本进程第一次看到这个状态算起，`state_change_seq` 一变就重算）/ `跑完了`。
  有会话刚变成 blocked 时底栏喊一声「等你：标题」。
- 光标停在跑着的会话上时，右栏每 3 秒重读尾 40 句，只把比现有第一句更新的并进去（高亮句不变、
  视口留在顶上）；**焦点在右栏、右栏被滚离顶部、正在输入右栏查询或开着全文浮层时不并**，先攒在
  `probe.fresh`，标题里写「新 +N 句，回顶上就刷」。一句都接不上（一下多了 40 句以上）就整个换掉。
- `Enter` 在哪一页、哪种会话上都是同一个动作：弹恢复确认框。
  在跑的会话主按钮变成「切过去」（Herdr：`herdr tab focus`）或「接管」（`claude --bg`：`claude attach <jobId>`，
  Herdr 能按目录找到 workspace 就开个 tab 在里面 attach，找不到就退出 TUI 在当前终端 attach，attach 的客户端
  可以 Ctrl+Z 退回 shell，会话继续跑）。在别的终端里交互跑着的接管不了，详情里说明「恢复会再开一份」。
- `X` 关掉 Herdr tab，先确认。
- `` ` ``（输入法下的 `·` / `｀` 也认；任何页面的 Herdr 会话上都行，恢复框「在跑」一行也有按钮）打开 `ovPeek`：`herdr agent read <pane> --source recent --lines 80 --format text`，每秒重读（`peekTickMsg`，关了就停），显示能放下的最后几行；`:`（`：`）聚焦输入框，`Tab` / `Shift+Tab` 在输入框和各按钮之间轮转，Enter 用 `herdr agent prompt` 作为下一句发出（agent 卡在问题上时 Herdr 会拒绝，报错原样提示）；`1` `2` `3` 第一次只是预备（提示「再按一次」），同一个数字再按才 `herdr agent send-keys`，Esc 取消；画面内容变了或过 5 秒（`peekArmFor`）预备自动作废；Enter（不在输入时）= 切过去。herdr 失败时带上它自己的 stderr（`herdr.text`）。
- `Z` 一次关掉空闲的 Herdr tab：记录文件 `capture.IdleAfter`（4 小时）没写、不在 working / blocked、没有「等你」或没看过的输出（`need`），确认框列出来、焦点在取消。
- `Space`（或 `Ctrl+G`）只做一件事：会话已经在 Herdr tab 里跑就切过去，其余同 `Enter`（只打开操作框；项目分组标题上是折叠 / 展开）；右栏焦点时是向下翻页。
- 会开进程、开 tab、往 agent 发东西的动作一律在对话框里由 Enter 执行。
- 在别的终端里跑着的会话（不是 Herdr tab、不是后台会话）不能再恢复一份：`PlanResume` 加一条阻断检查 `resume.check.running_elsewhere`，`runPlan` 先检查再决定退出 TUI，`tend resume` 同样拒绝。
- 新索引到达时如果一秒内有滚轮事件就先攥着，停下来再换 —— 滚着的时候重排列表，光标下的记录换了、
  右栏跟着换，看着像卡住。`TEND_TRACE=1`（或 `=路径`）把滚轮、按键和后台事件按毫秒记到 `~/.agent/tend/trace.log`，默认关；
  写盘在单独 goroutine 里走带缓冲的通道，UI 不等磁盘。真机复现「滚不回来」时对时间线用。

其它机器的 Agents 卡片只显示远端自己的运行状态，见 [remote.md](remote.md)「功能」。

## 布局阈值

终端按字符单元排版，按列数定死：

| 列数 | 布局 |
| --- | --- |
| ≥ 100 | 双栏，左 42% 列表 / 右 58% 预览 |
| 60–99 | 单栏列表；Enter 进详情页，再 Enter 或 `r` 恢复 |
| < 60 | 精简模式：去掉品牌行和 chips，每条只留标题与时间 |

## 视觉约定

- **不刷整屏背景色**，整体融入用户终端主题。背景色只用在局部反白的地方：
  选中卡片、激活的 chip、主按钮、警告框。
- 颜色成对定义（浅 / 深，`theme.go`）：`Init` 的 `askTheme` 在同一次写入里问背景色和设备属性（DA1），收到 `BackgroundColorMsg` 后 `setTheme` 按终端背景选一侧；DA1 的回复先到说明终端不回背景色，按深色；两者都没回就 1 秒后按深色。在此之前 `View` 不画内容（`themed`），浅色终端上不会先闪一帧深色。
  lipgloss v2 的 `Width` 含边框和内边距，框的宽度一律传外宽。输入框统一走 `newInput` / `newArea`（普通提示符和正文、反白光标跟正文色）。
- 画成框的元素：搜索框、5 个 chip、每张卡片、右侧预览面板、预览底部的「恢复目标」、
  浮层里的搜索框与按钮。列表在「会话」「收藏」视图不套外框，在「项目」视图套带标题的面板。
- 卡片高度固定（上下边框 + 标题 / 来源·项目+时间 / 标签三行），列表因此按「行」滚动而不是按「条」，
  否则半张卡片会被切在屏幕边缘。
- 终端只有一种字号，层级用 bold / 颜色 / 空行区分。
- **避开行内的 East Asian Ambiguous 字符**（★ ☆ → ▾ ▸）：它们在不同终端里宽度判定不一致，会把同一行的正文挤错位。默认 ASCII 图标，Nerd Font 私有区图标可选（见 [cli-and-config.md](cli-and-config.md)「配置」）。
  框线字符（`─ │ ╭ ╮ ╰ ╯`）不在此列：它们只画外框、不与正文同行混排，是所有终端 UI 的通用词汇。
- 所有宽度计算走 `go-runewidth`，中文两列；`len()` 会让右对齐列整体错位。
- 浮层用「剥色 + 压暗底图 + 按列合成」实现，终端没有真正的 z-order 和半透明。

## 键盘与鼠标

键位只有一张表：`internal/ui/tui/keys.go` 的 `bindings`，每条登记动作（`act`）、生效场景（`scope`：列表 / 恢复框 / 确认框 / 新会话框 / 交接框 / 瞄一眼）、分级（`tier`：导航 / 改 tend 自己的记录 / 启动进程·开 tab·发给 agent / 不可逆）、键（第一个是显示用的，其余是 Ctrl 替身和全角半角标点）、以及小写字母在输入法下的替代路线（`ime`：chip 行、恢复框按钮或另一个非字母键）。各处按 `keyAct(scope, key)` 分派；底栏（`fk` + `keyOf` / `footKeyOf`：小写字母带上标点替身显示成 `f/*`，或换成 Ctrl 键如 `Ctrl+Y`）、按钮（`keyed(键, 文字)`）、帮助页（`helpLayout` 只写分组、说明和动作，键列由表生成，成对的动作按 `j / k` 拼列）、帮助页的输入法说明（`imeNote`）、回收站守卫（`trashBlocked`：非导航、非 `D` 的动作）都从表里取；i18n 里的按钮和底栏文字不带键。`keys_test.go` 保证：同一场景没有重键；不用 `Alt`、`Ctrl+A`（Herdr 前缀）、`Ctrl+I/H/M/[`，`Ctrl+C` 只退出；启动类动作不在列表上；弹窗里 `Tab` 只移焦点、`Space` 只翻页；每个只有小写字母的列表动作都有非字母路线（按钮真的在恢复框里）；恢复框里启动类键都有对应按钮；恢复框里开着的按钮 `Tab` / `Shift+Tab` 都走得到，关着的走不到；帮助页列全每个动作；按钮 / 底栏文字不以键开头。恢复框里启动类键（`t p b s i c o`）按一下只移焦点（`focusKey`），框底一行灰字写明这条（键由 `startKeys` 从表里取），`r` 与 Enter 同义直接恢复。

搜索框有焦点时，快捷键字母都作为文字输入；方向键和翻页照常选记录，选过之后 `Enter` 直接起恢复确认。
中文输入法开着时小写字母被拿去组词，到不了程序；Ctrl 组合和大写字母（Shift+字母）输入法不拦。所以每个字母动作
都有输入法不拦的等价键：收藏 `*`（全角 `＊` 也认），其余 Ctrl 组合（`Ctrl+X` 完成、`Ctrl+E` 编辑、`Ctrl+Y` 复制、
`Ctrl+N/P` 上下、`Ctrl+G` 同 Space、`Ctrl+O` 排序）；归档没有 Ctrl 键——⚠️ `Ctrl+A` 是 Herdr 的前缀，按了它下一个键会被 Herdr 当命令（`x` 关 pane），tend 不绑定它，归档走操作框按钮，`D M X G J K N` 本来就是大写；`Enter` 打开的操作框里所有动作也都有
按钮（`←` `→` Enter 可达）；中文标点 `、` 当 `/`（搜会话）、`？` 当 `?` 用，`\` 的替身是 `Ctrl+S`；筛选走 `;` 进 chip 行。
筛选浮层自带搜索框，同理：导航用方向键或 `Ctrl+N/P`，`Space` 勾选，`Ctrl+U` 是清输入框（textinput 原义），
其余按键都是输入。单选框（状态 / 时间 / 项目）输入框空着再 Backspace = 清回默认并关框；多选框（标签）不这样，
勾选只能用「清空」按钮丢掉，免得误按全丢。
粘贴是单独的 `tea.PasteMsg`，只送进当前有焦点的输入框（浮层里的编辑框和筛选框、本会话查找框、顶部搜索框），没有焦点的输入框忽略它，列表上粘贴不触发任何动作。

**鼠标默认开启**，`tend tui --no-mouse` 关掉。支持：点标签页切视图、
点 chip 起对应筛选器、点输入框聚焦且光标落到点的那一列（搜索框、目录选择器、恢复框改标题、编辑框的标题 / 标签、设置里的文本项、对话查找框；摘要多行框只聚焦）、点卡片选中、双击卡片起恢复确认、
点「项目」分组标题折叠、滚轮翻条、浮层按钮（清空 / 取消 / 应用 / 恢复 / t 改用当前终端）可点。

点击不靠坐标计算：渲染时每个可点元素登记一个区域（行号 + 列区间 + 动作），
鼠标事件反查最后登记的命中项。浮层按盒内相对坐标登记，合成时整体平移；
浮层激活时底图的区域全部作废，避免点穿。

捕获鼠标会接管终端原生的文本选择，所以 tend 自己做拖选：按下记起点，拖动时选中行去色、选中段反白，
松手把屏幕上显示的文字（按阅读顺序，去掉边框和两端空白）送进剪贴板，底栏提示复制了多少字。
要终端原生选择就按住 `Shift`（iTerm2 是 `Option`）拖，或 `--no-mouse`。所有操作都有键盘等价方式。

滚轮按固定帧率处理，不跟鼠标：Ghostty 之类按像素发滚轮，触控板一甩几万个事件，逐个解析 + 渲染（每帧 2–4ms）会把 UI 卡住一分钟。`wheelInput`（`input_unix.go`）包住 tty 喂给 bubbletea：每次读到的一串同向滚轮序列，16ms 内已放行过就先记数不放；到下一帧按攒下的事件数算步数（请求 r 步放 √r×倍率 步，像鼠标加速：慢滚一帧一步，甩一下一帧十几步；倍率来自 `wheel_speed`：关 0 / 标准 1 / 快 2，设置面板里改，立刻生效），放最后一条序列的 `wheelStep`×步数 份；被读边界切断的半截序列两头都丢（攥着等下一次读会吞掉下一个按键）。到模型的事件再攒到 `wheelTickMsg`（16ms）一次应用，没动（列表到头、浮层到底：`scrollMax`）就不画，View 回上一帧缓存。每 `wheelStep`（3）个事件走一步（列表一张卡片、对话一行）。Windows 上没有 tty 层的丢弃（控制台输入由 bubbletea 自己读，`input_windows.go` 的 `terminalInput` 返回 nil），只剩模型层的 16ms 合帧和「没动就不画」。
